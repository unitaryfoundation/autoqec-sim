    autoqec-sim¶

    Circuit-level evaluation of stabilizer codes under device noise, in one call and without sampling, for codes from any source.

    What is autoqec-sim?¶

    autoqec-sim evaluates stabilizer codes under device noise. One call builds the syndrome-extraction memory experiment of any stabilizer code, CSS or not, applies a noise model with sourced device parameters, and returns the logical error per round, the exact circuit-level distance, and the dominant fault sets explained back to gates and qubits, without sampling or a decoder.

    The evaluator builds an R-round memory circuit with one ancilla per generator in a hook-aware gate order, derives stim's detector error model 1, and scores it at one of four tiers: a closed-form maximum-likelihood proxy over low-weight fault sets, exact maximum likelihood or a lookup decoder, BP+OSD 23, or Tesseract 4. The proxy is exact to leading order at circuit distance up to 6, ranks like BP+OSD over random codes (Spearman 0.78 to 0.90), and lands within the sampling error of 50,000 Tesseract shots on the 5x5 surface code at five rounds. The Evaluate a code page has the fields, the tiers, the validation, and the limits.

    Candidates can come from anywhere. The package ships three proposers and the tools that verify what they find: a SAT-population pipeline over the codes of 5, an evolutionary search, and a PPO agent in the gate-by-gate formulation of 6, all on a batched Aaronson-Gottesman tableau with a bit-identical torch and CUDA path. The experiments record what each has found: over 2,150 SAT-designed codes the code-capacity ranking carries no information about the circuit-level rate, the gate-by-gate agents rediscover the small codes and reach distance 3 on every lattice tried but do not scale past about 16 qubits under a sparsity constraint, and a schedule synthesizer raised the fault distance of the qldpc-challenge [[49,13,4]] circuit from 2 to 3.

    Quick Example¶

    Install with pip install git+https://github.com/unitaryfoundation/autoqec-sim, then evaluate the rotated surface code under three rounds of depolarizing noise:

    from autoqec_sim import evaluate_code
from autoqec_sim.noise import presets

# Rotated surface code [[9,1,3]], qubits on a 3x3 grid, row-major.
surface = [
    "XXIXXIIII", "IIIIXXIXX", "IXXIIIIII", "IIIIIIXXI",
    "IZZIZZIII", "IIIZZIZZI", "ZIIZIIIII", "IIIIIZIIZ",
]

# Three noisy rounds under uniform depolarizing noise at 1e-3, scored by
# the closed-form low-weight maximum-likelihood proxy (no decoder).
result = evaluate_code(surface, presets.depolarizing(1e-3), rounds=3)
print(f"error per round {result.p_round:.2e}  d_circ {result.d_circ}")

# The most probable minimum-weight undetectable fault set, as circuit errors.
top = result.dominant_faults[0]
print(f"{top.basis} basis, probability {top.probability:.1e}, {len(top.mechanisms)} mechanisms:")
for loc in top.locations:
    print(f"  {loc.pauli:7s} after {loc.gate} on {loc.qubits} at tick {loc.tick}  ->  {loc.targets}")

    Key Features¶

    • Evaluate a code

      evaluate_code: logical error per round, exact circuit-level distance up to weight 6, and the most probable undetectable fault sets as circuit locations, for CSS and non-CSS codes, at a closed-form proxy tier or with a sampled decoder.

    • Noise models with sourced parameters

      Device presets for IonQ Forte, IBM Heron, a long ion chain, and the qldpc-challenge recipe; biased, correlated, and leakage-aware channels, device timing, and connectivity through one noise interface that also noisifies a stim.Circuit of your own.

    • Verification independent of the objective

      Exact distance, weight enumerators, and the sparsest generator basis for every code; the rediscovery regression checks each found code against its reference.

    • Proposers

      The SAT-population pipeline of the experiments, an evolutionary search, and PPO with action masking and a permutation-equivariant policy, with an LDPC sparsity constraint and the memory objective as a reward; the torch backend runs the kernels on CUDA.

    For a fixed code, autoqec-schedule trains a PPO policy on the exact circuit fault distance of the syndrome-extraction circuit and confirms the best CX-layer schedule at rounds = d. See Commands.

    What's New¶

    Since release 0.2.0, main adds evaluate_code, the Tesseract tier, the proxy at circuit distance 5 and 6 through the enumeration of weight-5 and weight-6 undetectable fault sets, the SAT-designed-code experiments, and one documentation page per experiment.

    Release 0.2.0 added the noise module as the autoqec_sim.noise subpackage, with biased, correlated, and leakage-aware channels, device timing, topologies, and sourced presets for IonQ Forte, a long ion chain, IBM Heron, and the qldpc-challenge recipe; the LDPC constraint as a hard constraint or a reward penalty; the PPO agent, which matches the evolutionary search on every rediscovery target with 3 to 17 times fewer state evaluations; the memory objective with its fidelity tiers; and the torch backend with two fused CUDA kernels.
