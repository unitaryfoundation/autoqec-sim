    Evaluate a code under a device profile¶

    evaluate_code(code, profile) builds the R-round syndrome-extraction circuit of a stabilizer code in both memory bases (the circuit of the memory objective), applies a noise profile (a device preset or any autoqec_sim.noise.Profile), and returns a CodeEvaluation with the logical error per round, the exact circuit-level distance per basis, and the most probable undetectable fault sets explained back to circuit locations. The code is a StabilizerCode or its stabilizer generators as Pauli strings, CSS or not.

    evaluate_code(code, profile, *, rounds=None, scale=1.0, tier="proxy",
              shots=20_000, min_failures=0, max_shots=None, seed=0,
              connectivity="all_to_all", max_faults=10)

    rounds defaults to the code's exact distance; scale multiplies every rate of the profile; connectivity is "all_to_all", "square:RxC", or a memory_objective.Layout. The gate order of the extraction circuit is the hook-aware order of the memory objective, shared by the two bases.

    Example¶

    The whole script is docs/examples/evaluate_code.py. The first part runs in half a second.

    from autoqec_sim import evaluate_code
from autoqec_sim.noise import presets

# Rotated surface code [[9,1,3]], qubits on a 3x3 grid, row-major.
surface = [
    "XXIXXIIII", "IIIIXXIXX", "IXXIIIIII", "IIIIIIXXI",
    "IZZIZZIII", "IIIZZIZZI", "ZIIZIIIII", "IIIIIZIIZ",
]

# Three noisy rounds under uniform depolarizing noise at 1e-3, scored by
# the closed-form low-weight maximum-likelihood proxy (no decoder).
result = evaluate_code(surface, presets.depolarizing(1e-3), rounds=3)
print(f"error per round {result.p_round:.2e}  d_circ {result.d_circ}")

# The most probable minimum-weight undetectable fault set, as circuit errors.
top = result.dominant_faults[0]
print(f"{top.basis} basis, probability {top.probability:.1e}, {len(top.mechanisms)} mechanisms:")
for loc in top.locations:
    print(f"  {loc.pauli:7s} after {loc.gate} on {loc.qubits} at tick {loc.tick}  ->  {loc.targets}")

    error per round 9.09e-03  d_circ {'Z': 3, 'X': 3}
Z basis, probability 1.4e-06, 3 mechanisms:
  X4      after DEPOLARIZE2 on (14, 4) at tick 16  ->  D12 D13
  X1      after DEPOLARIZE2 on (13, 1) at tick 14  ->  D12 L0
  X6      after DEPOLARIZE2 on (14, 6) at tick 15  ->  D13

    The three data-qubit X faults, each the data half of a two-qubit depolarizing channel after a CZ from a Z-check ancilla (qubits 13 and 14), multiply to a logical X (the column {1, 4, 7} times the boundary check {6, 7}). Their detector flips cancel in pairs and only the observable L0 is left, so no decoder can see them. There are 176 such weight-3 sets in the Z basis with a summed mass of 8.7e-6 per shot (result.d_circ_mass["Z"]); the list holds the ten most probable per basis.

    # Monte Carlo with Tesseract: 20,000 shots per basis, each distinct syndrome
# decoded once. Needs the `tesseract` extra.
sampled = evaluate_code(surface, presets.depolarizing(1e-3), rounds=3, tier="tesseract", shots=20_000)
print(f"tesseract error per round {sampled.p_round:.2e}")
for basis in ("Z", "X"):
    s = sampled.per_basis[basis]["sampling"]
    print(f"  {basis}: {s['failures']} failures in {s['shots']} shots, {s['distinct_syndromes']} distinct syndromes")

    tesseract error per round 8.49e-03
  Z: 248 failures in 20000 shots, 2798 distinct syndromes
  X: 257 failures in 20000 shots, 2797 distinct syndromes

    Tesseract 1 decodes the detector error model as it is, without graphlike decomposition, so it applies to non-CSS codes and to the correlated channels of the device presets. The proxy above (9.09e-3) and the sampled tier (8.83e-3 with the lookup decoder at the same shots and seed) agree with it within shot noise on this code. Distinct syndromes are decoded once, so the 20,000 shots per basis cost about 2,800 decoder calls each, a few seconds on a laptop.

    What comes back¶

    CodeEvaluation is a frozen dataclass; to_dict() gives plain Python types for JSON.

    Field Content
    p_round logical error per round of tier, summed over the Z and X memories
    per_basis per basis, the dictionary of the memory objective: p_fail per shot, p_round, decoder, sampling (shots, failures, distinct_syndromes, seconds) for the sampling tiers, mechanisms, detectors, two_qubit_gates, layers, expected_faults per shot, and d_circ, d_circ_count, d_circ_mass
    d_circ, d_circ_mass per basis, the exact circuit-level distance (None above 6) and the summed probability product of its minimum-weight undetectable fault sets, computed whatever the tier
    tier, rounds the tier used and the number of noisy rounds
    dominant_faults DominantFault entries over both bases, most probable first

    Tiers¶

    tier Estimate Cost Needs
    proxy failure probability of the maximum-likelihood decoder restricted to fault sets of weight at most two, closed form from the DEM, exact to O(p^3); at circuit distance 5 or 6, where that form is zero, weight at most three through the weight-5 and weight-6 undetectable sets, exact to O(p^4) O(M^2) in the M mechanisms; 0.1 to 0.5 s per code at n = 9; about 20 s per basis for the 5x5 surface code at five rounds stim
    sampled exact maximum-likelihood decoder when detectors + observables <= 20, else a lookup decoder over the same weight-2 sets; Monte Carlo shots per basis, distinct syndromes decoded once stim
    bposd the board's pinned BP+OSD decoder 23; Monte Carlo as sampled, slower per syndrome ldpc (uv run --with ldpc)
    tesseract Tesseract most-likely-error search 1 on the full DEM; Monte Carlo 1 to 2 ms per distinct syndrome on the surface-code DEM tesseract extra

    The proxy and the lookup decoder are leading-order estimates. They hold while the expected number of faults per shot (per_basis[b]["expected_faults"]) stays below about one; above that, use tesseract or bposd. The memory objective page has the benchmark of the tiers against each other and the regime of each preset.

    Install the Tesseract tier with the extra (PyPI carries development releases of tesseract-decoder only):

    pip install "autoqec-sim[tesseract] @ git+https://github.com/unitaryfoundation/autoqec-sim"
uv run --extra tesseract python docs/examples/evaluate_code.py    # in this repository

    Dominant faults¶

    The circuit-level distance d_circ of a basis is the smallest number of DEM mechanisms whose combined effect flips no detector and some observable, found exactly up to weight 6 (pair tables to weight 4, the cluster search of memory_objective.undetectable_logicals beyond). dominant_faults lists, per basis, the max_faults most probable of these minimum-weight sets (a basis with d_circ of 7 or more contributes no entries). Each DominantFault carries:

    Field Content
    basis "Z" or "X"
    mechanisms indices into the error instructions of dem.flattened(), the mechanism order of memory_objective.dem_signature
    probability product of the mechanism probabilities
    locations one FaultLocation per mechanism

    A FaultLocation comes from stim's explain_detector_error_model_errors(dem_filter=..., reduce_to_one_representative_error=True) on the noisy circuit: gate is the noise instruction (DEPOLARIZE2, PAULI_CHANNEL_1, M for a measurement flip), qubits its targets, pauli the flipped Pauli product ("Y10", "Z10*X7", or "flip Z9" for a measurement flip), tick the number of TICK layers before it, and targets the detectors and observables the mechanism flips ("D12 L0"). Several circuit errors usually produce the same mechanism (the data half of every two-qubit channel on a qubit in the same layer, for one); stim reports one representative. gate is "?" when stim cannot attribute a mechanism to a single circuit error.

    The same enumeration is available on any DEM signature as memory_objective.undetectable_sets(sig, wmax=6, limit=10), which returns the weight, the count, and the most probable sets; its weight and count agree with exact_dcirc whenever the distance is at most wmax. memory_objective.undetectable_logicals(sig, wmax) returns every irreducible undetectable logical set up to wmax as arrays, weight by weight.

    A distance-5 code¶

    In a distance-preserving circuit for a distance-5 code no fault set of weight at most 4 is undetectable, so the weight-2 proxy is zero. The proxy tier then escalates to weight 3: memory_objective.undetectable_logicals lists every weight-5 and weight-6 undetectable logical fault set by a cluster search over the detector hypergraph, and the 3-subsets of those sets are the only weight-3 fault sets the decoder can get wrong (proxy_weight in per_basis reports 3). The 5x5 rotated surface code at five rounds under depolarizing noise at 1e-3:

    # A distance-5 code: the 5x5 rotated surface code at five rounds. No fault
# set of weight at most 4 is undetectable, so the weight-2 proxy is zero and
# the proxy tier escalates to weight 3 through the weight-5 and weight-6
# undetectable sets (a cluster search over the detector hypergraph, about
# 20 s per basis for this 2,100-mechanism model).
from autoqec_sim.known_codes import rotated_surface

d5 = evaluate_code(rotated_surface(5), presets.depolarizing(1e-3), rounds=5)
print(f"error per round {d5.p_round:.2e}  d_circ {d5.d_circ}  proxy weight {d5.per_basis['Z']['proxy_weight']}")
for basis in ("Z", "X"):
    s = d5.per_basis[basis]
    print(f"  {basis}: {s['d_circ_count']} weight-5 undetectable sets, mass {s['d_circ_mass']:.1e}, p_fail {s['p_fail']:.2e}")
top = d5.dominant_faults[0]
print(f"{top.basis} basis, probability {top.probability:.1e}, {len(top.mechanisms)} mechanisms")

    error per round 9.73e-03  d_circ {'Z': 5, 'X': 5}  proxy weight 3
  Z: 13485 weight-5 undetectable sets, mass 7.3e-08, p_fail 2.36e-02
  X: 13522 weight-5 undetectable sets, mass 7.1e-08, p_fail 2.41e-02
Z basis, probability 1.2e-09, 5 mechanisms

    The search visits 2.3e7 states per basis on this 2,107-mechanism model and takes about 25 s per basis; the hook-order search for the 25-qubit code adds a second. Tesseract with 50,000 shots per basis gives 1.05e-02 per round (1282 and 1286 failures) in 16 minutes, 8 percent above the proxy, at 6.0 expected faults per shot, outside the regime where a leading-order estimate is guaranteed to hold. Beyond distance 6 the proxy is zero again; the search cost grows about twentyfold per unit of weight.
