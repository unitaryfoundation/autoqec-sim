    Related work¶

    What exists around each part of this package, as of October 2026, from a survey that walked the reference lists of the closest papers, the papers citing them, and the surrounding topics. Every entry below was checked against its arXiv or publisher record. Items with public code are marked.

    Automated code and encoder discovery¶

    The gate-by-gate formulation this package's search layer uses, an agent appending Clifford gates to a stabilizer tableau under a Knill-Laflamme reward with the connectivity graph as the action space, is that of 1, whose code, QDX, is public and reached distance-5 codes at 11 to 17 qubits and a [[20,13,3]] code; composite "gadget" actions extend it to distance 7 23. The same simulator and agent were turned to fault-tolerant state preparation for a fixed code in 4 (code public). Earlier reinforcement learning for codes deformed a surface code toward a target logical error rate 5 and discovered few-qubit feedback strategies 6; later work searched tensor network code geometries 78 and reduced stabilizer weights toward LDPC codes 9. Variational discovery of codes and encoders predates the tableau formulation: a Knill-Laflamme loss on connectivity-constrained circuits 1011, neural-network code states 12, autoencoders 13, state-distinguishability losses with device runs 14 and their extensions to concatenation and logical operations 1516 (code public), Riemannian optimization over code subspaces 17, and variational graphical codes 18. Equivariant policies over tableaux appear in Clifford synthesis 19; the non-cumulative-objective RL of 20 is benchmarked on the same encoder task.

    Evolutionary search for codes exists at the gate-sequence level 21 and over binary stabilizer strings to 20 qubits 22, and annealing reaches 50 qubits 23. Exact and exhaustive methods frame the problem differently: additive codes over GF(4) 24, the classification of self-dual additive codes 25, every stabilizer code to 9 qubits 26, all distance-3 codes 27, codeword-stabilized search as clique finding 28, and, in 2026, SAT: code design with hardware and physics constraints, proved NP-complete and solved to 100 qubits 29 (code public), phantom codes 30, and machine-checked distance certificates 31. Above 20 qubits the field designs codes by program evolution with large language models 323334 (the IBM code is public), by multi-agent orchestration with circuit-level evaluation 35, by Bayesian optimization with a learned logical-error predictor 36 (code public), by game-theoretic search 37, with decoders in the loop 3839, with hardware calls in the reward 40, and by multi-agent RL that includes a syndrome-extraction agent 41. Sparse codes can also be grown from seeds 42.

    Where this package stands: its search layer is a reimplementation of 1 in numpy with a torch path, at parity on the distance-3 targets of QDX's published set and behind it on larger ones (experiments/qdx_targets/REPORT.md). Its evolutionary agent is simpler than 22. Nothing in its discovery mode is new.

    Noise- and hardware-tailored codes¶

    Codes tailored to biased noise are a mature line: the XY and XZZX surface codes 4344, Clifford deformations, uniform and per-qubit 4546, bias-tailored LDPC codes 47, and in 2026 per-qubit deformation optimized from calibration data 48 (code public). Picking a small code from device error data goes back to 49 and was benchmarked against hardware in 50; distance choice from drifting calibration appears in 51, an ion-chain noise model with tailored extraction circuits in 52, and a full-stack empirical comparison in 53. The device presets here (Forte 54, a long ion chain 55, Heron 5657) and the heavy-hex lattice 58 are the inputs this package evaluates codes against.

    Where this package stands: its reward is the undetected single-fault mass of the encoding circuit under such a profile, and its memory objective is a multi-round experiment with a decoder. The nearest prior objectives are code-capacity 14948 or circuit-level for a fixed code 4; 35 evaluates at circuit level inside a closed LLM loop. The comparison in experiments/sat_codes/REPORT.md shows the two levels ranking the same codes differently.

    Encoder synthesis and fault-tolerant preparation¶

    For a fixed code, SAT-optimal fault-tolerant state preparation 59, tableau-search encoders for arbitrary stabilizer codes 60, noise-aware LDPC encoder resynthesis 61, SMT search for fault-tolerant Clifford circuits 62, architecture-aware stabilizer synthesis 63, and heuristic and optimal CNOT and Clifford synthesis 64 (code public) all compete with RL-found encoders on gate count, and 64 claims to win. A benchmark for AI-assisted synthesis 65 and a FAIR circuit library 66 appeared in 2026.

    Syndrome-extraction schedules¶

    Hook errors and CNOT ordering are as old as the surface code 6768. Automated scheduling is a 2026 topic: Monte Carlo tree search with decoder feedback 69 (code public), MaxSAT-guided rewrites 70 (code public), SMT depth-optimal compilation 71, RL rewarded by sampled logical error rate 72, left-right circuits with effective-distance proxies 73, hook-free surface-code schedules 74, short Shor-style sequences 75, flag-style extraction for small codes 76, detector-error-model-driven design 77, and the result that hypergraph-product codes keep their distance under any schedule 78. The schedule synthesizer here is RL over the CX-layer assignment with the exact circuit-level fault distance as the reward, which none of these use; its one result, on the [[49,13,4]] entry of 79, is a demonstration rather than a benchmark against them.

    Distance, verification, and simulation¶

    Exact distance here is enumeration to 20 qubits. Public tools go further: randomized information-set distance 80, parallel Brouwer-Zimmermann 81, and SAT, MILP, and heuristic code and circuit distance in one package 82; the problem is NP-hard 83, has been cast as quantum annealing 84, and for large LDPC codes is bounded from above by heuristic witness search 85. Weight enumerators are not a complete invariant, and local-Clifford equivalence has its own test 2586; the generator weight this package calls w* is the optimal generator weight of 87. Fault-counting sensitivities 88, Pauli diagnostics 89, and tensor-network enumerators 90 are further evaluation tools. Stim 91 underlies the noise and detector-error-model work; Clifft 92 is the Unitary Foundation's near-Clifford sampler; 93 reports hardware error-detection experiments from the same group.

    Evaluating codes under circuit-level noise¶

    The evaluator's proxy is a leading-order count of the minimum-weight undetectable fault sets of the extraction circuit, decoded by maximum likelihood over those sets alone, and its ingredients are standard. Counting malignant pairs of fault locations bounded circuit-level failure to leading order in the threshold proofs of 94; 95 enumerated the minimum-weight fault configurations of a periodic surface-code circuit to give its low-rate logical error analytically for arbitrary per-gate Pauli noise; and 96 showed that the number of minimum-weight failing configurations, the entropy term, sets the low-rate logical error alongside the distance, which is what separates codes of equal distance on the same footprint here. Where the leading order ends, sampling takes over; the rare-event splitting method of 97 reaches rates below what direct sampling gives, and this package raises the noise scale instead of implementing it. The reference decoders are minimum-weight matching in its sparse-blossom implementation 98, BP+OSD [@roffe2020; @panteleev2021], and the Tesseract most-likely-error search 99. Which of 39 Clifford deformations of the distance-3 surface code is best depends on the decoder, with PyMatching against BP+OSD at Pearson 0.88 under one circuit-level noise model and 0.30 under another 100, which is why the validation here (experiments/proxy_tesseract/REPORT.md) is against a near-maximum- likelihood decoder. Circuit noise models built from device parameters go back to the superconducting-inspired SI1000 model of 101; the presets here are the same kind of object, assembled from public specifications. Flag-qubit extraction with two extra qubits for distance-3 codes 102 and with flag ancillas for arbitrary distance 103 is what the one-flag option (one flag on each generator of weight three or more) approximates. Subsystem codes are measured through their gauge generators in the stabilizer formalism of 104, with the bare logical operators of 105; the Bacon-Shor code 106 and the heavy-hexagon code 58 are the two shipped. The published memory experiments the evaluator is compared against (experiments/hardware_comparison/REPORT.md) are the distance-3 surface codes of 107108, the Steane code on a trapped-ion processor 109, the toric and bivariate bicycle 110 codes on a 40-ion chain 55, and the heavy-hexagon subsystem code 111; that comparison is of the package's model on its own circuit against each paper's reported number, not a prediction of the devices.

    Where this package stands: the leading-order estimator applies the counting of 95 and 96 to the extraction circuit of an arbitrary stabilizer code through stim's detector error model 91, with the enumeration carried to weight-3 fault sets at circuit distance 5 and 6; the decoders, noise models, and experiments it is checked against are prior work.
