    Modules¶

    Module Contents
    autoqec_sim.tableau Batched Aaronson-Gottesman tableau 1, one dense uint8 array of shape (batch, 2n, 2n+1). Gates H, S, S_DAG, CNOT, CZ, SWAP, and Pauli frames X, Y, Z, each applied to selected batch elements with per-element qubit indices through gather/scatter indexing (no Python loop over the batch). ActionTable resolves a vector of discrete actions with one pass per gate type. Conversion to and from stim.Tableau 2 for cross-checks.
    autoqec_sim.symplectic GF(2) elimination, kernel, solve; symplectic product as a float32 GEMM plus parity; logical-operator extraction by symplectic Gram-Schmidt 3 on N(S)/S; completion of a stabilizer set to a full tableau.
    autoqec_sim.errors Enumeration of all Paulis up to a weight, probability weighting under per-qubit Pauli channels, top-M dominant errors.
    autoqec_sim.reward Knill-Laflamme 4 reward of 5, r = -sum_mu lam_mu K_mu, vectorized over the batch and chunked over the error set. Detection is decided from the n+k code rows of the tableau: an error is undetected iff it commutes with every stabilizer and anticommutes with some logical (degenerate errors in S count as detected, no linear algebra needed). Also a batched exact-distance reward, a low-weight-stabilizer penalty (excludes codes padded with idle qubits), and a composite reward.
    autoqec_sim.code StabilizerCode read off an encoding tableau or built from Pauli strings (general non-CSS, symplectic form). Exact distance for n <= 20 by enumerating N(S) or low-weight Paulis, whichever is cheaper; randomized information-set upper bound with a witness for larger n (the symplectic version of research/kit/surrogate.py in 6); CSS test 78; weight enumerators of S and N(S).
    autoqec_sim.known_codes [[5,1,3]] 910, Steane [[7,1,3]] 8, Shor [[9,1,3]] 11, rotated surface 12 [[9,1,3]] and [[16,1,4]] (rotated_surface(d) builds any distance), [[4,2,2]].
    autoqec_sim.graphs all-to-all, linear chain, square, triangular, heavy-hex 13 builders and a kind:size spec parser. Every builder delegates to autoqec_sim.noise.topology; from_topology, Graph.to_topology, and as_graph convert between the environment view (n, sorted edge tuple) and the noise module's graph, so the action space and the noise profile's placement check share one edge set.
    autoqec_sim.ldpc LDPC sparsity of a stabilizer group, batched: exact minimum bottleneck generator weight w* and a sparsest basis with its maximum qubit degree (bit-packed GF(2) elimination over the enumerated group, n - k <= 14), greedy fallback for larger codes, feasibility test ldpc_feasible, reward penalty ldpc_penalty, per-action mask greedy_action_mask (greedy bound, or the exact feasibility test after every two-qubit gate for n - k <= 15). LdpcObjective: reward and success criterion of an LDPC-constrained [[n, k, d]] target in one of four forms (penalty, unnormalized, final, schedule), exact w* on candidate states only; see "LDPC constraint".
    autoqec_sim.env CodeDiscoveryEnv: gymnasium-style reset/step/observation without a gymnasium dependency. State is the batched tableau; actions are single-qubit gates on every qubit and two-qubit gates on the edges of a connectivity graph (either graph class; env.topology is the noise-module view); observation is the tableau bits, the (n-k) x 2n check matrix, or a flat vector; reward modes dense 5, delta, sparse; per-element auto-reset; rollout of fixed action sequences; optional hard LDPC constraint (ldpc_w_max, modes terminate, mask, final) and feasible_action_mask().
    autoqec_sim.circuit_noise Circuit-level reward under a autoqec_sim.noise.Profile (board, ion, Heron presets and their variants), a preset name, or any stim.Circuit -> stim.Circuit callable (the placeholder depolarizing model is kept). The gate list is laid out as a TICK-layered skeleton so the profile's timing and idle model apply; every fault mechanism of the noisy circuit is propagated through the rest of the encoding circuit (one GF(2) product against the symplectic map of the circuit suffix; fault_set_reference is the stim PauliString.after version, about twenty times slower, kept as the cross-check) and scored with the Knill-Laflamme kernel; dem_undetected_mass cross-checks the result against stim's detector error model.
    autoqec_sim.memory_objective Multi-round memory objective: an R-round syndrome-extraction circuit for arbitrary (non-CSS) stabilizer generators with one ancilla per generator, hook-aware gate orders, commutation-respecting batches, optional one-flag ancillas, all-to-all or square-lattice layouts with routed long-range gates; the autoqec_sim.noise profile with its timing model, stim's detector error model, and three fidelity tiers for the logical error rate per round (closed-form low-weight maximum-likelihood proxy with exact d_circ, exact ML or lookup-decoder sampling, pinned BP+OSD 1415 sampling). MemoryReward is the environment reward; see docs/experiments.md and docs/memory_objective.md.
    autoqec_sim.search Random search and an evolutionary search over gate sequences, one batched rollout per generation.
    autoqec_sim.regress The rediscovery regression and the autoqec-regress CLI.
    autoqec_sim.backends.torch_backend Opt-in torch versions of the gate kernels, ActionTable, the symplectic product, and the parity masks (undetected_mask, in_stabilizer_mask, batched_distance, the rewards) on cpu or cuda tensors, same names and semantics as the numpy functions, bit-for-bit agreement tested. The mod-2 reduction and both commutation tests run as one in-place remainder_(2) and one matrix-vector product, without the int64 copy and the boolean reductions of the numpy path. numpy_reward_adapter plugs a torch reward into the environment. See docs/gpu.md.
    autoqec_sim.agents.ppo PPO 16 agent (PyTorch, CPU): clipped objective, GAE 17, shared value head, entropy bonus, action masking, over the batched environment. torch is an optional dependency (rl extra) and is imported lazily.
    autoqec_sim.agents.ppo_regress The rediscovery regression run with PPO instead of evolutionary search, reusing the targets, reward, replay, and verification of regress, plus the PPO-only 4x4 rotated-surface target [[16, 1, 4]] (1M env steps, full budget only).
    autoqec_sim.experiments.noise_aware The noise-aware discovery experiment (three noise profiles, three settings, five PPO seeds each, cross-evaluation, known-code baselines, report and figures); see docs/experiments.md.
    autoqec_sim.experiments.scaling The RL scaling probe: diagnosis of the 4x4 failure, one-change-at-a-time variants of the agent on [[16, 1, 4]] (curriculum, macro actions, equivariant policy, batch and entropy, episode cap), and LDPC-constrained [[n, k, 3]] targets at n = 12 to 16; see docs/experiments.md.
    autoqec_sim.experiments.ldpc_scaling The LDPC constraint forms above n = 9: unnormalized, final, and schedule against the regression's penalty form on [[12, 2, 3]] and [[16, 4, 3]] with w_max = 4, all-to-all and square graphs, three seeds, equivariant policy, fixed budget per run; see "LDPC constraint" and experiments/ldpc_scaling/REPORT.md.
    autoqec_sim.experiments.ldpc_sparsity Sparsity as a property of the trained policy: the shaped (dense per-step term in reward units), terminal (count-unit signal at any candidate), and mask (greedy w* action mask) variants against unnormalized at equal budget on [[12, 2, 3]] (all-to-all, square:3x4) and [[16, 4, 3]] (square:4x4), measured as the fraction of at-distance terminal states inside the bound; see experiments/ldpc_sparsity/REPORT.md.
    autoqec_sim.experiments.ion_chain The noise-aware 4x4 protocol of gpu_scale (equivariant PPO, batch 1024, three profiles, cross-evaluation) on all-to-all connectivity at n = 16, the connectivity of an ion chain, with and without S in the gate set; the report compares the all-to-all codes under the ion profile with the 4x4 lattice cells of experiments/gpu_scale/runs/, the rotated surface code's lattice and all-to-all encoders, and the n = 16 known codes; see experiments/ion_chain/runs/REPORT.md.
    autoqec_sim.experiments.topologies The three-topology run matrix: the PPO agent alone on square, triangular, and heavy-hex lattices at two qubit-count tiers, one objective ([[n, 1, 3]], no idle qubit, H and CNOT on lattice edges, 50-gate cap), common metrics per cell (steps to success, exact d, w*, qubit degree, weight enumerators, Heron and board fault masses, rotated surface baseline); see docs/experiments.md.
    autoqec_sim.experiments.memory_objective Benchmark of the memory objective's tiers on five codes and three profiles, rank correlation on random distance-3 codes, the XZZX 18 bias-sensitivity test, the lattice-routing comparison, and the PPO smoke run with the memory reward; see experiments/memory_objective/REPORT.md.
    autoqec_sim.experiments.memory_ppo The noise-aware 4x4 protocol of gpu_scale with the memory objective as the noise term (R = 4 rounds, all-to-all layout, proxy tier in training) on four cells (chain 0.25 bare and one-flag, board 0.25, Heron 0.05), three seeds, and a second run without the LDPC term, with a gate-count term, the sampled tier outside the proxy's regime, and the sparsest generator basis; score re-evaluates the discovered codes, the encoder-objective 4x4 codes, and the rotated surface and XZZX codes under every profile at the proxy, sampled, and bposd tiers; see experiments/memory_ppo/REPORT.md.
    autoqec_sim.experiments.figstyle The one matplotlib style every figure of the package uses (6.5 in text width, standard heights, panel labels, profile colors).

    Not included: Clifft integration and cuQuantum kernels.

    Layout¶

    src/autoqec_sim/         package
src/autoqec_sim/backends/  torch backend of the gate kernels and parity masks (opt-in; docs/gpu.md)
src/autoqec_sim/agents/  PPO agent, its two policies (flat MLP, permutation-equivariant), and its regression
src/autoqec_sim/experiments/  noise-aware, scaling, LDPC-form, and topology experiments and the shared figure style
tests/                   pytest suite (tableau vs stim, codes, rewards, env, noise hook, LDPC, regression, PPO, noise-aware experiment, torch backend vs numpy, the quick-start example)
experiments/<name>/      one directory per experiment: REPORT.md, figures/, launcher scripts, and runs/ (raw output, not tracked)
experiments/regression/  regression.json (evolutionary) and regression_ppo.json (PPO), full budget; regression_ppo_4x4_seed{0,1}.json (PPO, the 4x4 target)
experiments/regression/figure.py  the rediscovery-cost figure of the README and the regression page, from those files
benchmarks/profile_tableau.py  CPU throughput and memory profile of the tableau, reward, and environment (docs/profile.md, docs/gpu.md)
benchmarks/bench_cuda_kernels.py  the fused CUDA kernels against the torch path (docs/gpu.md)
tools/reproduce.sh       fresh venv, tests, both reduced regressions (docs/reproduce.md)
tools/release.sh         the release procedure (docs/development/releasing.md)
docs/examples/           the quick-start scripts, snippeted into the documentation and checked against the README
