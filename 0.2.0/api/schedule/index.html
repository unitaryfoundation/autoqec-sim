    Schedule synthesis¶

    autoqec_sim.schedule_env ¶

    Syndrome-extraction schedule synthesis for a fixed CSS code, as an episodic MDP whose reward is the circuit's fault distance.

    The code is fixed. What the agent chooses is the CX layer structure of one extraction round: which (check, data qubit) couplings happen in which time slot. That is the quantity the board's circuit tier scores (qldpc-challenge/verify/circuit_tools.build_css_memory: "The schedule -- the thing the tier scores -- is the CX layer structure"), and the one that moved the measured logical error rate by 5 to 300x in the project's matched pairs under a fixed code, noise model, and decoder.

    Episode. The Tanner edges of H_X and H_Z are visited in a fixed order; at each step the agent picks a time slot for the current edge. A slot is feasible when no edge already in it shares the check or the data qubit (the layer must be a matching), and, without interleave, X edges use the first slots_x slots and Z edges the following slots_z so the two blocks never overlap in time and every detector is deterministic. With interleave the two blocks share one set of slots; a schedule whose detectors are not deterministic (the ordering criterion of the board's interleaved builder fails) is invalid and scored invalid_reward.

    Reward. At the end of the episode the schedule is built into the board's memory experiment (research/circuit_autogen.build_memory), the canonical noise recipe is applied, stim derives the detector error model, and the fault distance is read either exactly up to weight exact_wmax (autoqec_sim.memory_objective.exact_dcirc, the right tier when the code distance is at most 4 or 5) or by the board's own randomized information-set search (circuit_tools.ris_dem, an upper bound). The reward is min_basis d_circ / d minus depth_penalty per CX layer beyond the lower bound, so a schedule that reaches the code distance in the fewest layers scores 1. d_circ is clamped to d: nothing above the code distance is credited, since the tier does not credit it either.

    Everything the reward depends on is the board's code, imported from a checkout of qldpc-challenge (QLDPC_CHALLENGE environment variable, default ../qldpc-challenge beside this repository), so a schedule found here is scored exactly as the board would score it on submission.

    step(actions)

    Assign the chosen slot to each episode's current edge. Returns (obs, reward, done, info); reward is zero until the final step, where every episode is scored at once.

    reward_of ¶

    reward_of(s: dict) -> float

    Reward of a score_layers result. The fault distance is clamped to the code distance. In the exact tier the number of minimum-weight undetected fault sets at the limiting basis is a dense tie-breaker inside one distance level: (d_circ + 1 / (1 + count)) / (d + 1), so one fewer such set is progress and any schedule at d_circ + 1 beats every schedule at d_circ. In the ris tier no count exists and the term is a constant.

    score_layers ¶

    score_layers(
    code: BoardCode,
    layers,
    rounds=None,
    bases=("Z", "X"),
    tier="exact",
    exact_wmax=4,
    ris_trials=2000,
    ris_seed=0,
    ris_seconds=None,
)

    Fault distance of a schedule under the board's own pipeline.

    Returns {"valid": bool, "d_circ": {basis: int|None}, "min": int|None, "layers": int, "seconds": float, "detail": {...}}. In the exact tier a basis whose search finds nothing up to exact_wmax reports exact_wmax + 1 as a floor (the exact value is at least that); in the ris tier None from the search is reported as code.d since the tier credits nothing above the code distance anyway.

    coloring_baseline ¶

    coloring_baseline(
    code: BoardCode, samples=20, seed=0, **score_kw
)

    The board builder's own schedule family: a greedy proper edge coloring of each Tanner graph, X block then Z block, shuffled by seed. Returns one score dict per sample with the layers attached.

    autoqec_sim.schedule_cli ¶

    Schedule synthesis for one board code: coloring baseline, then PPO.

    autoqec-schedule 49-13-4 --board /path/to/qldpc-challenge --updates 40

    Writes <out>/ (default schedule_out/<slug>/) with baseline.json (the board builder's own schedule family, scored), train.jsonl (one line per PPO update), best.json (the best schedule found, its layers, and a deep-search confirmation of its fault distance), and log.txt.

    train_ppo ¶

    train_ppo(
    env: ScheduleEnv,
    updates: int,
    log,
    out_path: Path,
    *,
    lr=0.0003,
    epochs=4,
    minibatch=256,
    clip=0.2,
    ent_coef=0.01,
    vf_coef=0.5,
    seed=0,
    hidden=(256, 256),
)

    Fixed-horizon PPO over whole episodes. Every update collects batch_size complete schedules, scores them at the terminal step, and fits the policy on the batch_size * E transitions with a terminal reward and gamma = 1.
