    Backends, agents, search¶

    autoqec_sim.backends.torch_backend ¶

    torch versions of the tableau gate kernels and of the parity masks.

    Every function here has the name and the semantics of its numpy counterpart in autoqec_sim.tableau, autoqec_sim.symplectic, and autoqec_sim.reward, but takes and returns torch.Tensor objects on whatever device the tableau lives on (cpu or cuda). The tableau layout is the same (batch, 2n, 2n + 1) uint8 array, so torch.from_numpy(tab) and tab.cpu().numpy() move a state between the two backends without conversion.

    Parity test. The numpy path computes the float32 product of the error set against the code rows, casts it to int64, masks the low bit, and runs two boolean any() reductions; on the CPU the cast and the reductions are about 80 percent of the reward (docs/profile.md). Here the product is reduced mod 2 in place in float32 (remainder_(2), exact because the entries are integers below 2n) and the two commutation tests are one matrix-vector product against a weight vector: stabilizer columns weigh 2k + 1 and logical columns 1, so the score of an error is s (2k + 1) + l with s the number of anticommuting stabilizers and l the number of anticommuting logicals, and the error is undetected iff 1 <= score <= 2k (s = 0 and l >= 1). The intermediate is one float32 (batch, chunk, n + k) block, a third of the numpy path's peak, and no boolean (batch, chunk, n + k) array exists at all.

    Gate kernels are the gather and scatter operations of the numpy module on torch tensors. Grouping a vector of actions by gate type needs one nonzero per gate type, which on cuda synchronizes with the host; the gate kernels are about one percent of an environment step, so this is accepted rather than fused.

    autoqec_sim.agents.ppo ¶

    Proximal policy optimization over the batched code-discovery environment.

    The agent follows Olle et al. (arXiv:2311.04750) in spirit: a policy over discrete gate choices, conditioned on the current stabilizer tableau, and trained on the Knill-Laflamme reward that the environment returns at every step. The batch dimension of autoqec_sim.env.CodeDiscoveryEnv is the vectorized environment; one call to env.step advances every episode by one gate.

    Components (Schulman et al., arXiv:1707.06347):

    • clipped surrogate objective with ratio clip clip_eps;
    • generalized advantage estimation with gamma and gae_lambda;
    • a value head sharing the trunk with the policy, squared-error loss weighted by vf_coef;
    • an entropy bonus weighted by ent_coef.

    Action masking. The environment's action table already contains only the gates the connectivity graph allows, so nothing there needs masking. The agent still applies a mask through EnvAdapter: (i) a static mask from graph_action_mask when the table has actions on edges outside a given graph (a policy trained on all-to-all and evaluated on a lattice), (ii) a dynamic mask that forbids undoing the previous gate when it is an involution (H, CNOT, CZ, SWAP, Paulis), and (iii) any mask the environment itself exposes through an action_mask() method returning a (batch, num_actions) boolean array. Masked actions receive the logit MASK_LOGIT (a large negative number) before sampling.

    Policies. PPOConfig.policy chooses the actor-critic from autoqec_sim.agents.policies: the flat MLP ("mlp"), the per-qubit permutation-equivariant network ("equivariant"), or "auto" (the default: equivariant from 12 qubits on, mlp below). Both take the same observation and mask from EnvAdapter and return logits in the order of the environment's action table plus a value.

    torch is imported lazily so that the rest of the package works without it.

    EnvAdapter ¶

    Observation encoding and action masks for CodeDiscoveryEnv.

    observation: "tableau" encodes the 2n x 2n X and Z bits of the whole tableau (destabilizers and stabilizers; the sign column is dropped since the reward does not depend on it), "check_matrix" encodes only the (n - k) x 2n stabilizer block (the observation of Olle et al.). Bits are mapped to {-1, +1} floats.

    action_mask ¶

    action_mask() -> np.ndarray | None

    (batch, num_actions) boolean mask of allowed actions, or None if nothing is masked.

    PPOConfig dataclass ¶

    Hyperparameters of PPOAgent.

    policy selects the actor-critic (autoqec_sim.agents.policies): "mlp" (flat MLP with layers hidden), "equivariant" (per-qubit permutation-equivariant network of width equivariant_hidden), or "auto" (equivariant when the environment has at least EQUIVARIANT_MIN_QUBITS = 12 qubits, mlp otherwise). The flat MLP at n >= 12 needs rollout_steps * batch of about 16 x 1024 and ent_coef = 0.001 to make progress (experiments/scaling/REPORT.md).

    PPOAgent ¶

    PPO over a CodeDiscoveryEnv with auto_reset semantics.

    The environment is switched to auto_reset = True and dense reward; the episode ends when the state reward reaches env.success_threshold (a code satisfying every term of the reward) or after env.max_steps gates. Truncated episodes are treated as terminal for the value bootstrap.

    device (default "cpu") is the torch device of the network and of the update: observations, masks, and rollout buffers are copied to it, actions and values copied back. The environment and its reward stay numpy on the host either way. On "cpu" every copy is a no-op and the trajectory is the one of the version without the argument.

    equivariant_actor_critic ¶

    equivariant_actor_critic(
    n: int,
    entries: list[tuple],
    hidden: int = 128,
    rows: int | None = None,
)

    Permutation-equivariant actor-critic over the tableau.

    entries is the environment's action table ((gate, q1, q2) with q2 = -1 for single-qubit gates); logits are assembled in its order. The observation is the flat rows x 2n block of X and Z bits (rows = 2n for the tableau observation, n - k for check_matrix). Qubit q gets the 2 rows features of its two columns (X bit and Z bit of every row), a shared MLP embeds them, a mean over qubits gives the context, and a second shared MLP maps [own, context] to the qubit embedding. Single-qubit gate logits come from a per-gate linear head on the qubit embedding; two-qubit gate logits from a head on the concatenated embeddings of the ordered pair; the value from the mean and max pooled embeddings.

    autoqec_sim.agents.policies ¶

    Actor-critic networks for the PPO agent.

    Two policies share the interface model(obs, mask=None) -> (logits, value) with obs the flat {-1, +1} observation of autoqec_sim.agents.ppo.EnvAdapter, mask an optional boolean (batch, num_actions) tensor, logits of shape (batch, num_actions) in the order of the environment's action table, and value of shape (batch,). Masked actions receive the logit MASK_LOGIT.

    mlp Flat MLP trunk over the whole observation with a linear policy head and a linear value head. Its first layer has obs_dim x hidden weights, so the parameter count grows as n^2 and the policy has no notion of which input bit belongs to which qubit. equivariant Per-qubit shared MLP over the qubit's two tableau columns plus a mean-pooled context, per-gate heads on the qubit embedding (single-qubit gates) and on the ordered pair of embeddings (two-qubit gates), value head on the mean and max pooled embeddings. Relabelling the qubits permutes the logits accordingly. This is the policy the RL scaling probe found to reach [[16, 1, 4]] on every seed where the flat MLP at batch 256 never did (experiments/scaling/REPORT.md).

    resolve_policy implements the "auto" choice of autoqec_sim.agents.ppo.PPOConfig: the equivariant network from EQUIVARIANT_MIN_QUBITS qubits on, the flat MLP below.

    torch is imported inside the builders so that the module imports without it.

    autoqec_sim.search ¶

    Search agents over gate sequences, evaluated in batches by the environment.

    EvolutionarySearch keeps a population of fixed-length action sequences (-1 entries are no-ops, so sequences may be shorter than the cap). Every generation is one batched rollout. The next population is the elite, mutated children of tournament-selected parents (point replacement, insertion, deletion, one-point crossover), and a fraction of fresh random sequences. With random_frac = 1 it degenerates to random search.

    A PPO agent over the same environment is in autoqec_sim.agents.ppo (optional torch dependency).

    autoqec_sim.regress ¶

    Known-code rediscovery regression.

    For each target the search agent, from a seeded start, must produce an encoding circuit on the target's connectivity graph whose code has the target parameters [[n, 1, 3]] with no stabilizer element below a target-specific weight (so a smaller code padded with idle qubits does not count). The result is verified independently of the reward: the circuit is replayed, the code is read off the tableau, its distance is computed exactly, and its weight enumerators are compared with the reference code. Equal enumerators of S and N(S) are a necessary condition for equivalence under qubit permutations and local Cliffords; the report labels the match as such rather than as a proof of isomorphism.

    LDPC targets add the sparsity constraint of autoqec_sim.ldpc (Target.ldpc): a hard bound w_max on the generator weight enforced in the environment (mode "mask" or "terminate") or as a reward penalty (mode "penalty"). Two of them are exclusion targets (expect_success=False): the search must not find a distance-3 code within budget. For 5 qubits with w_max = 3 this is a theorem (the [[5,1,3]] code is unique and every nontrivial stabilizer has weight 4); for 7 qubits with w_max = 3 it is an empirical statement bounded by the budget, contrasted with w_max = 4, which admits the Steane code and is found in the same budget. The verification of every LDPC target reports min_max_generator_weight (exact w*) and the maximum qubit degree of the sparsest basis found.

    Run autoqec-regress --budget full for the release numbers (restarts until the enumerators match) and --budget reduced for the quick check that the pytest uses.

    LdpcSpec dataclass ¶

    LDPC constraint of a target. mode is "mask", "terminate", or "final" (hard constraint in the environment), "penalty" (reward term -penalty_scale * excess, see ldpc.ldpc_penalty, the form of the n <= 9 regression targets), or "objective": the reward and success criterion are one autoqec_sim.ldpc.LdpcObjective in the form form (default ldpc.DEFAULT_LDPC_FORM, the form the comparison in experiments/ldpc_scaling/REPORT.md selected for n >= 12; penalty_scale is its scale).
